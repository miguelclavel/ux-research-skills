# Usability test plan

Test whether people can do what the product is for, without being told how.

## Steps

1. **Goals:** the two or three questions this test answers ("Can first time visitors start a quote from the homepage?").
2. **Participants:** five to eight per distinct group finds most big problems. Include people who use assistive technology when you can.
3. **Tasks as scenarios:** a realistic goal, no interface words, no hints. "Your renewal went up by 20%. Find out if you could pay less", not "Click Compare quotes".
4. **Success criteria** for each task: what counts as success, partial success and failure, decided before testing.
5. **Metrics:** task success, time on task, errors, a single ease question after each task (one to seven), and SUS at the end if you need a benchmark.
6. **Script:** intro and consent, think aloud practice, tasks in a sensible order, post task questions, wrap up. Neutral prompts only: "What are you looking for?", "What would you do next?"
7. **Setup:** device, prototype links, recording, note taking template, a pilot run with a colleague first.

## Output

The plan with goals, participants, each task with its scenario and success criteria, metrics, and the full moderator script.

## Don't

- Don't help, lead or explain during tasks. Don't test five features in one session; test the core flow well.
